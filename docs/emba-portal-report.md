# Member portal implementation

The `/emba` route intentionally shows **Sign-in is not configured yet** until a trusted browser session provider is implemented. It does not query the database in that state. It does not use legacy identity cookies, query/header person IDs, assistant bearer credentials, or a demo identity. A server-only AsyncLocalStorage fixture supports isolated tests only; production cannot install it.

Implemented member UI and first-party server actions:

- Inspect global and selected-trip private preferences separately, including archived/review-needed records; create persistent wants and time-boxed intents, and save version-checked corrections with operation IDs. UTC time bounds are validated, and corrections cannot move an item's scope or kind. Saving does not publish or commit. Inspection persists audit before output.
- Grant explicitly selected assistant actions with an expiry and an authorized named trip context or personal context, list scopes and expired/revoked states, revoke access, and inspect the latest access history. Grants are not OAuth credentials.
- Accept recipient-bound invitations; organizers select a scope and list/create/revoke invitations through the existing authorization service. Token creation is explicitly not email delivery.
- Accessible labeled forms, pending fieldset disabling, inline action status/errors, stale-correction recovery, empty states, and mobile layout using existing Loop styling.
- Scoped trip resource listing, source/version inspection, conflict-aware evidence search, organizer upload/correction/process/retry/delete. Announcements show current signature and key verification; publishing/corrections stay explicitly unavailable without a configured signer.
- Activity publication, revision-bound conditional commitments, withdrawals, dependency consent, name disclosure, finalized disclosed names, deadline resolution, lifecycle controls, safe organizer reports, and explicit attendance/assessment correction/deletion.
- Creator/manager activity revision and reopening with explicit review of changed terms and fresh commitment requirements. A bounded inbox supports caller-bound cursor pages, expired-cursor recovery, and an explicit human acknowledgement action; rendering or assistant polling does not acknowledge an update.
- Personal planning bundles with source versions and incomplete, insufficient, conflicting and truncated evidence states.
- Two-step assistant review for commitment, identity disclosure and publication: strict structured parsing, authoritative current activity/role checks, exact payload display and separate checkbox approval. No query or pasted input autoexecutes a mutation. Approval returns a single-use confirmation ID, not an executed commitment.
- Provider-independent structured Want proposal review: only strict structured fields within a 4096-byte UTF-8 payload are accepted, the candidate remains transient, and the member sees the candidate beside the current want when a conflict exists. A stale version or changed context cannot be accepted. A matching archived or review-needed want requires explicit reactivation. A separate first-party acceptance saves the explicitly reviewed want through the existing optimistic memory service, including exact operation replay. This does not infer from conversations or classify crises.
- Pilot export download and explicit pilot deletion via recent-authentication-gated services. No form input supplies authentication time. UI explains retained shared name/phone, organization publications, and unresolved backup retention.

`lib/emba/portal-session.ts#getPortalPrincipal()` is the integration point for the future verified browser session provider. `app/emba/data.ts#readPortalData(principal)` returns personal memory, leases, and audit records. Actions always obtain the principal again and check first-party authority; Next Server Actions retain default same-origin CSRF enforcement.

Limitations: no production sign-in, browser demo authentication, remote OAuth acceptance, invitation email sending, configured announcement signer, conversation compiler, or crisis classifier. The structured proposal review expects JSON from a trusted member workflow and stores only the accepted structured want; it does not persist unaccepted candidates or raw conversations. Global and selected-trip memory are each limited to 100 current records with a truncation notice; connections/audit show the latest 100. Publication and source management use explicit structured fields, not document extraction from arbitrary uploaded binary files.

Validation: React Testing Library exercises explicit form submission, intent bounds, named assistant scope selection, stale error rendering, unselected grant defaults, structured Want conflict review, and separate exact-payload review/approval. Portal action tests use an isolated PostgreSQL-compatible fixture and test-only verified session to verify contextual intent creation, correction boundaries, invalid UTC dates, forged assistant scope denial, and proposal acceptance only after a checked review. Service tests verify that unaccepted candidates leave no memory row, audit failure denies review, a later member correction wins over a stale candidate, and context cannot move. Authentication tests exercise unconfigured rendering, unauthenticated actions, strict review binding, and rejection of test session injection in production. No browser or remote acceptance is claimed.

### Late authorization during page loading - 2026-11-06

The member page now refreshes accessible loop metadata after its other asynchronous reads, then rechecks first-party identity, selected-loop read access and management authority before returning. Demotion hides previously loaded invitation emails and role/member administration data. Membership or identity removal returns the unavailable page. Revocation of another organization removes its earlier names/paths from trip and assistant-context selectors while preserving the still-authorized selected trip.

Four real-database page regressions reproduced stale output before these changes and now pass on PGlite and native PostgreSQL. Resource upload/correction/process/delete controls and invitation acceptance/revocation controls are shared between the production portal and synthetic browser harness, avoiding duplicate test-only forms. These checks do not claim to retract already delivered data or verify production provider sessions.

### Trip-panel snapshot validation - 2026-11-07

TripPanel now refreshes management/publication permissions after asynchronous activity reads and returns its unavailable state on late identity or membership loss. A final transaction validates loaded document versions, processing status and passage readiness under source locks. Withdrawal or correction during loading discards the stale panel; a selected document from another trip also receives its own final scope authorization check. This protects the composed snapshot, not changes after transaction completion or information already delivered.

Seven database-backed component cases cover unchanged access, organizer demotion, membership removal, identity revocation, source withdrawal/correction and other-trip source access removal. The initial reproduction passed its positive control and failed all five initial regressions. Final focused verification passed 45 portal tests and 24 native PostgreSQL tests (trip panel, page authorization and knowledge), plus TypeScript and focused lint. The assistant grant label now describes trip knowledge and planning context, and explains context-specific grants and the additional private-preference access needed for personalized planning. The browser driver's matching label was updated; no new browser run is claimed for this slice.
